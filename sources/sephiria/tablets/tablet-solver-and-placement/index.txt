3:T1b5f,<p>The fastest way to place tablets in Sephiria is not to work it out by hand. <strong>SephiriaSolver</strong>, a free browser tool maintained by the player forestsquirrel, takes the tablets you hold and searches for the grid layout that maximises your buffs — and since its Rulesets update it can be told <em>what you actually want</em> ("at least three cells at +5, the rest as high as possible") rather than one blunt global goal. This page explains the tool's modes, marks and limits, using its author's own documentation, so you know which button to press for which situation.</p>
<p>If you need the underlying rules first — tablets are emitters that push a level onto other cells, and a cell's level is the level of the artifact sitting in it — start with the <a href="/tablets/all-tablets/">tablet families</a> and the <a href="/guides/inventory-grid/">inventory grid</a> pages.</p>
<figure class="fig"><img src="/images/sephiria-inventory-transference-panel-1200.webp" srcset="/images/sephiria-inventory-transference-panel-800.webp 800w, /images/sephiria-inventory-transference-panel-1200.webp 1200w" sizes="(max-width: 768px) 100vw, 720px" alt="Sephiria Transference panel with options to increase or reduce artifact level and rotate" width="1200" height="675" loading="lazy" decoding="async"><figcaption>Transference: increase level, reduce level, rotate. <h2>The four-step loop</h2>
<ol><li>Select the tablets you have.</li><li>Pick how long the solver may search.</li><li>Click Solve.</li><li>Choose whichever result fits your needs and apply it to the grid.</li></ol>
<p>Search time is a budget: <strong>Quick</strong> (1 s), <strong>Standard</strong> (5 s), <strong>Deep</strong> (15 s), <strong>Max</strong> (30 s). The author's note is that longer searches find <em>better</em> layouts, not just more of them; use Quick while you are iterating and Deep or Max "when you want the last slot squeezed out for a build." You can cancel mid-search and keep what has been found.</p>
<h2>Two engines: Legacy and Rulesets</h2>
<p>The solver has two engines, switchable at the top of the panel.</p>
<p><strong>Legacy</strong> is the original three global modes:</p>
<div class="tw"><table><thead><tr><th>Mode</th><th>What it optimises</th></tr></thead><tbody><tr><td>Perfect Coverage</td><td>Fill every slot while maximising total buff</td></tr><tr><td>Maximize</td><td>Push individual slots to the highest values while maximising total buff</td></tr><tr><td>Target Value</td><td>Fill as many slots as possible with a value you choose, while maximising total buff</td></tr></tbody></table></div>
<p><strong>Rulesets</strong> replaces the single goal with a list of rules, each reading <em>{Exactly / At least / At most} N slots with buff {= / ≥ / ≤} V</em>. You can stack as many as you like and drag them to set which rule gets first pick of the good slots. A final <strong>Rest of slots</strong> setting — Maximize, Coverage or Target — decides what happens to cells no rule claimed, and it is always lowest priority so it can never outbid a rule.</p>
<p>The author explains the problem Rulesets solves better than we can: if you want +5 on just two slots, Target Value wastes buff pushing <em>every</em> slot toward 5, and pinning slots with target marks forces a fixed layout. A rule asks for a count without naming which cells, so the solver keeps its freedom "and stops spending buff where nothing asked for it."</p>
<p>The tool validates a ruleset before solving and says outright if it is impossible with your tablets and slot count. If it solves but cannot satisfy everything, it reports which rule fell short and by how much "rather than pretending it's a clean win."</p>
<h2>Marks</h2>
<p>Two kinds of mark work in any mode and alongside Rulesets:</p>
<ul><li><strong>×2 Slot</strong> — for the <strong>Mystic</strong> combo. Mark the slots you want doubled; up to three can be marked since v2.0.</li><li><strong>Target Slot</strong> — click a cell and set a value it must equal or exceed. The solver treats targets as first priority in every mode. A target that is already satisfied also counts toward a matching rule, so you do not budget the same slot twice.</li></ul>
<h2>Reading the results</h2>
<p>The best three layouts show as cards. Everything else sits behind <em>Browse all results</em> — a Deep search can return a couple of hundred — in a table that sorts by any column and filters by total buff, covered slots, or "at least N slots with buff ≥ V." Columns show how many slots got each value, so you can compare the <em>shape</em> of two layouts at a glance, and any row applies straight to the grid. Identical layouts are collapsed into groups by default; click the badge to expand one.</p>
<h2>Grid size, merging and edge cases</h2>
<p>Three details from the changelog matter for real runs:</p>
<ul><li><strong>Starter Grid</strong> button sets the early-game <strong>6×4</strong> inventory, for players who have not yet bought the expansions on the <a href="/guides/destiny-inscription/">Destiny Inscription</a> tree. The maximum grid the tool supports was raised to <strong>60 slots</strong> after a player showed the in-game grid can be pushed far larger than the tool assumed.</li><li><strong>Merged tablets</strong> (from the Tablet Combiner) now inherit the activation position of their parts — a bug reported by a user and fixed in v2.1.</li><li><strong>Items that interact with the grid</strong> — those that need a specific placement or react to neighbours — are part of Rulesets as of the Items Update, and all tablets are in the tool "including those which let items ignore positional constraints." The <strong>Curse</strong> tablet from the Skeleton costume and the <strong>Wedge</strong> tablet were added after reports, which tells you the list is community-maintained: if a tablet is missing, the author asks to be told.</li></ul>
<p>The tool tracks the game: v2.0 added the 1.0 patch's tablets "with adjustments where the patch notes changed them" and noted two tablets still to be found in-game. The 1.0.19 notes list seven new tablets, so if you hold one the solver does not know, that is why.</p>
<h2>What the solver cannot know</h2>
<p>It optimises numbers on cells. It does not know that a +5 cell is wasted on an artifact whose maximum level is 3 — that check is yours, and the in-game <strong>Q / E</strong> preview while hovering an artifact is the fastest way to make it. It does not know your combo plan, which is why the <a href="/builds/build-routes/">Ingenuity breadth route</a> and the depth routes want different shapes from the same tablets. And it cannot see two 1.0.30 fixes that changed how imprinting behaves in play: a tablet no longer disappears without imprinting when its activation conditions are unmet, and undiscardable tablets can no longer be fed to the Combiner.
